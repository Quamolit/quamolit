## 全屏舞台与 DOM 浮层

- 动画 Canvas 覆盖整个页面视口，位于导航和控制面板之后；不是嵌在侧栏旁的剩余空间，也不是要求调用浏览器 Fullscreen API。允许较大的可滚动 DOM 浮层，但提供可收起/恢复按钮和键盘焦点。
- Canvas CSS 尺寸与 backing store 分开：实际像素按视口 × DPR 更新。暂停时 resize/DPR 变化仍重绘，不重置时间/Model。禁止只用 CSS 拉伸低分辨率位图。
- 每个作品明确 responsive 或 contain 的构图策略、逻辑坐标和指针逆变换；视口参与组件声明时必须更新对应版本。同一时间的视口变化不能被缓存吞掉。
- 只有浮层实际覆盖区域拦截事件；不使用透明全屏 DOM 遮罩。舞台输入走 #34 的命中/捕获路径，绘制不负责注册事件。触摸滚动限制按作品需求局部设置。
- 桌面、窄屏、DPR 1/2、暂停后 resize、浮层收起/展开与导航返回均验证；截图分别保存纯画布和包含浮层的页面。支持 reduced-motion/暂停、分享显式时间与 seed，作为真实作品的后续交付门禁。
- Canvas2D/WebGPU 复用同一声明、时间和输入。全屏增大实际像素成本，性能报告必须列分辨率、DPR、画质与透明覆盖率，不以铺满画布宣称性能提升。

首个布局切片是 `examples/retained-consumer/`：默认全屏 Canvas + 浮层，使用 contain 呈现既有 320 × 180 逻辑构图。它只展示公共 Calcit 保留 API，不是旧 demo 或艺术作品；宿主尺寸变化仅更新呈现变换，UI 中原有 `viewport` 参数仍是组件测试输入，不冒充通用响应式布局。`?fixture=1` 保留固定像素诊断模式，现有数值和像素断言不放宽。

## 艺术作品扩展

导航预留 `art` 分类，空分类明确显示尚未交付，不添加假作品链接。后续可从生成几何、动态构图、光色与粒子等方向选择具体作品；这些是方向，不是已确定作品名单。每件作品需要独立 ID、中文说明、预览图及固定时间/seed、操作指南、后端/回退和画质成本说明。

动画设计、组件声明、采样和 Scene/执行优化继续优先 Calcit；平台原语使用 js-ffi 类型化入口和定义级 inline/file。导航 HTML/JS 不承接艺术算法，不为了展示另写一套 JS renderer。先用恢复的真实动画推动 #49/#50/#53/#34，避免持续增加只有测试矩形的页面替代产品成果。
