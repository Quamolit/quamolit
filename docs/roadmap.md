# Quamolit 技术路线与阶段交付

计划版本：v2，2026-09-23。本文及 `verification.md` 是后续编码的共同约定；GitHub issues 管理进度，`work-items.md` 保存本次整理的任务规格与依赖。旧版 `vnext-design.md` 保留历史背景，其三阶段顺序已被本计划替代。

## 产品目标与当前事实

Quamolit 让使用者声明组件，通过函数和显式动画描述生成中间帧。框架负责把这些声明转成高效的网页动画执行路径，既支持普通交互 UI，也支持大量同类图元。应用拥有逻辑动画 Model，渲染器拥有可重建的执行缓存与宿主资源。

截至本次整理：#42 的 Calcit 0.19.1/runtime 升级及 #44 的 tick/paint 分离已合并；#45 的泛型顺序帧求值仍是独立 PR。`sample-at`、Motion IR、Scene IR、增量执行、WebGPU 和完整视觉 CI 均不能据此认定已完成。默认入口仍是 bootstrap。未来接手时以实际 main 和 PR 状态重新核对，不把这份历史快照当作实时进度。

## 两种时间语义

默认动画采用直接采样：`value = f(time, parameters)`。渐变、关键帧、周期运动等给定任意有限时间即可求值，不必从零逐帧走到该点，允许乱序、倒放和截图。草案入口称为 `sample-at`，具体名称由 #30 确定。

依赖历史的动画采用固定步长模拟：`state[n+1] = step(state[n], dt, inputs[n])`。显式保存 tick index、seed、输入记录及必要的检查点；重置和恢复可重复。草案入口称为 `step-simulation`。已有 `evaluate-at` 可作为迁移基础，但可变 elapsed 的顺序更新不自动具有固定步长或任意时间语义。部分有解析解的弹簧可直接采样，不必一律模拟。

同一时间只有在模型、动画、资源、视口及其他实际依赖均未变化时才能复用。资源 ready、输入事件或 DPR 改变不能被 time 相等吞掉。暂停通过显式模拟时钟表达；后台恢复的追帧上限与 seek 策略需有可观察行为。

Model 应保存 from/to/start/duration/easing 等过渡意图。打断时从当前采样值建立新过渡；位置连续和速度连续是不同契约。退出组件由稳定 key 与显式生命周期保留到动画结束，再释放资源；绘制过程不承担逻辑卸载。

## 组件、逻辑表示与执行计划

```text
声明式组件 + Model → Scene IR + Motion IR → 增量编译 → 保留执行计划
                                                       ↑
                                              时间、输入、资源版本
                                                       ↓
                           CPU 自定义采样 / GPU 标准采样或模拟 → 绘制
```

- **Scene IR** 表达图元、分组、变换、裁剪、层叠、事件目标、动画绑定及资源引用。逻辑 key 与物理 buffer slot 分离。
- **Motion IR** 是小而明确的带类型动画表达式集合，支持 CPU 参考求值以及明确子集的 WGSL 实现。任意 Calcit 纯函数保留 CPU 扩展路径，不进入可序列化的描述节点。
- **执行计划** 保存依赖、批次、绘制顺序、几何和宿主资源缓存。可在内部使用可变缓冲区，但必须按输入版本正确失效，不改变可观察语义。
- **资源表** 通过 ID/version 连接逻辑描述和宿主句柄，显式管理 loading/ready/error、缓存容量、释放与 device loss 后重建。

分别处理拓扑变更、几何/资源变更、属性变更和仅时间变化。不能强制每帧重新执行整个组件树、深比较所有节点、物化所有实例的中间对象，再全量打包上传。结构不变时复用静态结果，更新必要绑定与脏数据范围；以计数器证明这些行为。

## WebGPU 与回退

M2 必须交付真实 WebGPU 绘制路径。普通组件合法合批，instances 用一个逻辑图层表达大规模数据。共享几何和实例参数长期保留在 GPU；独立无历史运动优先在 vertex shader 采样，只有复用或工作负载证明需要时增加 compute pass。

有历史模拟在 M4 建立 GPU 常驻状态，定义资源 ID、seed、tick 和 checkpoint。普通帧不读回全量数据；测试与调试可以读取有界样本。剔除、间接绘制、render bundles、worker/WASM 均按瓶颈证据采用，不以技术名词作为完成目标。

Canvas2D 在 M2 提供基础语义参考，M3 补齐完整支持矩阵。回退边界是完整图层或子场景；避免每个图元跨后端复制。GPU 专属高级功能需声明其降级或不支持行为，不强求不存在的等价 fallback。设备探测与失败必须可诊断。

任何批处理都要保持合法绘制顺序；透明物体不能为减少 draw call 任意排序。必须定义预乘 alpha、颜色插值、组透明度隔离层、嵌套裁剪、文字排版和路径细分规则。跨后端采用明确数值/视觉容差，不能承诺浮点逐位一致。

## Milestones 与退出条件

| 阶段 | 主要交付 | 退出条件 |
| --- | --- | --- |
| M0 代表场景与性能基线 | UI 过渡、实例、文字/路径三个可运行夹具；最小视觉 CI；完整帧基准 | 固定输入可复现，原始数据及环境可审查，CI 真正执行浏览器测试 |
| M1 动画函数与组件契约 | 直接时间采样、固定步长模拟、Motion/Scene IR、身份及进入退出 | 乱序采样、打断连续性、重放和生命周期测试通过，迁移 API 有可编译样例 |
| M2 增量执行与 WebGPU 主路径 | 保留计划、资源表、批量 FFI、自动合批/instances、基础双后端、GPU 标准动画 | 真实 GPU 证据，时间变化不重建静态结构，同源场景双后端正确，回退/恢复通过 |
| M3 完整 2D 功能与应用迁移 | 文字路径等完整语义、独立交互、真实入口、扩展视觉 CI | 代表性应用运行，compile/release 对应真实入口，功能与画质矩阵明确 |
| M4 GPU 模拟与性能发布 | GPU 历史模拟、跨设备调优、后端/Use.GPU 决策与迁移发布资料 | 指定设备达到注明的目标，或明确记录未达范围；数据、恢复与回归证据齐全 |

阶段可以按已验证前置产物推进，不必等整个前一 milestone 关闭才开始所有工作；依赖见 `work-items.md`。性能与视觉检查贯穿各阶段，不在最后补做。Canvas 基础参考和首个 WebGPU 后端均在 M2，不以完整旧应用迁移阻塞 GPU 验证。

## 性能目标与证据

当前没有新架构实测吞吐。以下是待验证的工程目标，不是已实现性能：固定 1920×1080 实际像素、受控抗锯齿/混合/覆盖率，先在命名的现代集成 GPU 上测量，再扩展移动与独立 GPU。

| 负载 | 首要目标 | 扩展目标 |
| --- | --- | --- |
| 1k 混合 UI 节点 | 稳定 60 FPS；缓存文字与几何 | 简单场景 120 FPS |
| 10k 简单动画实例 | 稳定 60 FPS；低 CPU/上传开销 | 120 FPS |
| 100k 简单小实例 | GPU 路径压力测试 | 受控覆盖率下 60 FPS |

复杂路径、动态文字、滤镜和大面积透明叠加另设基准，不用图元数量推算性能。DPR、面积和叠加必须记录。60/120 FPS 的显示周期分别约为 16.67/8.33 ms，CPU/GPU 的流水线耗时不能简单相加或单独替代实际掉帧。具体测量、回归和视觉规则见 `verification.md`。

## 变更与接手规则

开始实现前核对 issue 依赖、已有 PR 和能力支持表；给出本 PR 的切片与验收项。提交后写明命令、版本、原始结果、限制和剩余项。部分交付写“推进 #N”，全部验收有证据后才自动关闭。

接口名、后端选择和第三方包可以在证据支持下调整；涉及本路线边界时，随代码提交设计记录：问题、候选、选择、语义影响、基准与迁移成本，并同步关联 issue。不得因旧实现存在而锁定旧技术，也不得在无测量时宣称新技术更快。

`calcit-lang/js-ffi` 继续封装可跨项目复用的 JS 生态基础能力，包括 DOM、Canvas2D、WebGPU、TypedArray 和通用批量/资源原语：公共入口优先由 Calcit 定义类型，必要的宿主 JS 实现留在上游包内。Quamolit 专属的 Scene lowering、动画与执行计划、资源/批次策略优先写在本仓库 Calcit 中；只有专属且无法合理用 Calcit 表达的宿主适配才放本仓库 `src/host/`。不以 JS 行数决定模块归属，也不把 Quamolit Scene 格式搬到通用库。具体守则见 [Calcit 优先的 FFI 边界](calcit-first-ffi.md)。Use.GPU 优先评估数据源/图层、增量执行与 shader 工具；引入完整 Live 运行时需证明它与 Calcit 组件模型的整合成本可接受。

参考：[Use.GPU 增量执行](https://usegpu.live/docs/guides-memoization)、[数据驱动图层](https://usegpu.live/docs/guides-data-driven-geometry)、[WebGPU 上传策略](https://toji.dev/webgpu-best-practices/buffer-uploads)、[性能测量边界](https://webgpufundamentals.org/webgpu/lessons/webgpu-timing.html)。这些是技术依据，项目验收仍以本仓库可复现证据为准。
