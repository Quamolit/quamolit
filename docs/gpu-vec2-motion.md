# Vec2 Motion 的真实 GPU 时间采样：M2 #52 切片

`quamolit.motion-gpu/lower-vec2` 产生的可序列化 `:supported GpuVec2Plan` 仍是逻辑描述。`quamolit.gpu-vec2-translation/prepare` 与 `frame-at` 现在用 Calcit 类型化地只接受 Vec2 tween（linear/smoothstep），把计划变为固定参数和绝对时间帧；常量计划显式返回 `unsupported`，无效 duration 或超出 f32 有限范围的参数也返回诊断。页面启动时准备一次并保留类型化计划，逐帧只附加时间，不重新解析 Motion。ID/version 已由上游带类型描述符及 `lower-vec2` 验证，不再在 JS 中重新解释序列化对象。原 `src/host/gpu-vec2-translation.mjs` 已删除。通用 WebGPU 资源和 uniform 最终校验仍由 js-ffi 提供；底层位移见 [js-ffi PR #107](https://github.com/calcit-lang/js-ffi/pull/107)，类型化 Calcit 入口与诊断见 [js-ffi PR #108](https://github.com/calcit-lang/js-ffi/pull/108)；Quamolit 当前引用 `0.1.46`。

`test/gpu-vec2.html` 从同一份 Calcit Scene IR 获取 10k 实例源，从同一 Vec2 Motion 描述分别得到 CPU 参考采样和 GPU 参数。Canvas 逐实例 `fillRect`，WebGPU 在 vertex shader 使用绝对时间平移整个保留式位置 buffer。固定实际像素 400×220、DPR=1，t=0/0.25/0.5/0.75/1 的锚点和背景像素须与 CPU 精确一致；页面初始化及按钮乱序重放，禁用后整图层回退 Canvas，重试重建资源。

应用内浏览器 `adapter=apple/false` 已实测 1→0→0.25 秒及回到 0.5 秒的两张画布可见一致；锚点 `234,88,12,255`、背景白像素均通过。0.37 秒的 GPU shader f32 位移读回为 `(107.19999694824219,94.80000305175781)`，Calcit CPU 参考为 `(107.19999999999999,94.8)`；0.81 秒分别为 `(177.60000610351562,112.4000015258789)` 与 `(177.60000000000002,112.4)`，均满足预先规定的逐分量阈值 `1e-5 + 1e-5*abs(expected)`。非整数时间只验证数值，不能把边缘覆盖率当作精确内区像素；整数坐标帧仍执行 GPU/Canvas 像素精确对照。0.81 秒截图可见 GPU 网格接近连续色块，而 Canvas 仍呈细网格，表明两后端的亚像素覆盖/抗锯齿语义尚不一致，不能因 f32 数值通过就宣称画面等价。热帧 10k 位置上传与 CPU 再复制均为 0，`draw=1、uniform=64、pipeline=1、buffers=2`；禁用后 Canvas 继续正确，重试上传 80,000 字节。64 字节 uniform 每帧包含时间与固定 tween 参数，尚未优化为只写 4 字节时间。诊断像素与 f32 读回会创建临时资源，不属于稳态绘制。

`yarn test:motion-gpu` 检查严格 Calcit 公共定义、支持/不支持分类、越界参数、计划序列化、无效时间和 CPU 数值对照；`yarn test:motion-browser` 检查无 GPU 的同源 Canvas 帧；`yarn test:webgpu-instances` 增加 GPU 专项。无头 Chromium 当前只有 `google/true` 软件 adapter，GPU 专项显式 SKIP，不算硬件通过。此次仅迁移逻辑归属，没有测量或声称性能提升。此前真实 GPU f32 证据只覆盖受限 Vec2 linear tween 与上游固定 seed 诊断扫描，**尚不能证明**亚像素/混合边缘等价、全部标准动画子集、吞吐或 FPS；这些仍留在 #52。真实设备意外丢失后的自动恢复与通用资源表留在 #51。
